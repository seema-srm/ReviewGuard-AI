# ReviewGuard quality baseline — November 11, 2026

Thirty reviewed synthetic cases, ten per target reviewer, were run once through
the complete three-agent workflow. All results are retained in
`baseline-2026-11-11.jsonl`; aggregate case averages are in
`baseline-2026-11-11.summary.json`. No inference retries or prompt changes were
made during this experiment. LangSmith and Langfuse tracing were disabled.

## Reliability across the full workflow

Every case ran every agent, giving 90 branch outcomes. Code quality succeeded
30/30 times and security succeeded 30/30 times. Test coverage succeeded 18/30
times and failed 12/30: nine `invalid_schema`, three `invalid_source_evidence`.
Consequently, only 18/30 workflows completed fully; 12 were partial. Its target
subset failures were `tc-04`, `tc-05` (schema) and `tc-08` (source evidence).
The sanitized reports do not retain rejected raw completions, so these categories
do not establish the exact offending field, phrase, or model-output root cause.

## Disagreements to inspect

- Code quality found all five labeled issues and produced no findings on the
  five negative cases. It rated `cq-02`, `cq-04`, and `cq-05` HIGH where the
  references say MEDIUM. This small synthetic sample does not establish general
  accuracy.
- Security found all five positive anchors. It additionally flagged `sec-07`
  for potential option injection into `ping` and `sec-10` for potential path
  traversal through the root argument. Both model descriptions explicitly depend
  on missing caller context. The fixed references mark these cases clean; treat
  the discrepancies as human-adjudication items before calling them confirmed
  false alarms.
- Test coverage's positive references list one expected scenario per case, while
  valid model output can contain up to five recommendations. `tc-01` produced
  four suggestions: boundaries, inverted bounds, invalid inputs, and NaN. Only
  one can match the single reference, so the other three count as extras under
  this scorer.
- Successful test-coverage negative cases (`tc-06`, `tc-07`, `tc-09`, `tc-10`)
  suggested additional edge scenarios despite supplied tests. Their validity and
  usefulness require human review; an unmatched recommendation is not
  automatically a technically incorrect recommendation.

## Interpretation and next work

This is an exact-evidence-anchor benchmark, not semantic validation of findings.
An anchor match can credit a recommendation about a different concern on the
same line, and legitimate additional scenarios can be penalized. Labels remain
fixed for this baseline; do not silently alter them to improve the score.

First investigate the test-coverage output-validation failures using bounded,
sanitized diagnostics that preserve the existing grounding checks. Next
adjudicate the coverage recommendations and the two security disagreements;
version any amended labels separately. Then make one targeted change and compare
against this frozen dataset/model with the same scorer. No improvement is claimed
by this baseline, and no second paid evaluation has been run.
